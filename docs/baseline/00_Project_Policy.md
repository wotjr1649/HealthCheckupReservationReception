# 1. CP 공통 정책

| ID | 구분 | 정책 |
|---|---|---|
| **CP-01** | 업무 가능일 | 운영요일 및 활성 휴무일 Master를 기준으로 업무 가능일을 판단한다. |
| **CP-02** | 운영요일 | 월요일부터 토요일까지를 기본 운영요일로 한다. |
| **CP-03** | 휴무일 | 일요일은 항상 업무 불가다. 월~토라도 활성 휴무일 Master에 등록된 날짜이면 업무 불가로 판단하며 상세 기준은 HOL Rule을 적용한다. |
| **CP-04** | 운영시간 | 업무 운영시간은 `09:00 <= 현재시각 < 18:00`으로 한다. 18:00부터 업무 불가다. |
| **CP-05** | 취소 처리 및 보존 | 예약·접수 업무 건은 취소 시 물리 삭제하지 않고 동일 데이터 행을 취소 상태로 변경한다. 취소 상태는 취소 시점에 따라 `예약취소(CNR)`와 `접수취소(CNC)`로 구분한다. 취소 건도 내역 조회 대상으로 유지하고 기존 상태로 복원하지 않는다. 재진행하려면 신규 예약을 생성한다. |
| **CP-06** | 변경 이력 | 상태전이 궤적은 별도 History로 관리하지 않는다. 현재 유효 데이터와 생성·최종수정시각을 관리하고, 이에 더해 Write Stored Procedure 호출이 **실제로 바꾼 컬럼마다 1행**의 변경기록(시각·조작자·대상 테이블·대상 키·컬럼명·변경전·변경후)을 남긴다. 데이터를 바꾸지 않은 호출은 기록하지 않는다 — 실패한 호출, 잠금 실패, 예상하지 못한 오류, 같은 값으로 덮어쓴 경우가 모두 여기에 해당한다. 변경기록의 값은 상한 길이에서 잘릴 수 있으며 복원의 근거로 사용하지 않는다. 열람용이다. |

## 1.1 공통 업무 가능조건

```text
현재일이 월~토
AND 활성 휴무일 Master에 등록되지 않음
AND 09:00 <= 현재시각 < 18:00
→ 공통 업무 가능
```

- 당일예약과 접수에는 3장의 별도 마감시간 정책을 추가 적용한다.
- UI의 Enabled/Disabled는 사전안내이며, 저장·상태전이 시 DB에서 현재 조건을 다시 검증한다.

# 2. EP 수검자 관리 정책

| ID | 구분 | 정책 |
|---|---|---|
| **EP-01** | 관리 단위 | `1수검자 = 1개의 수검자 Master`로 관리한다. |
| **EP-02** | 내부 식별자 | `수검자.PatientId`를 시스템 내부 수검자 식별자로 사용한다. DB에서 자동 생성하고 이후 변경하지 않는다. |
| **EP-03** | 차트번호 | 수검자 최초 저장 시 차트번호를 부여한다. 수기 입력할 수 있고 미입력 시 시스템이 자동 발급한다. 차트번호는 전체 수검자에서 고유해야 한다. |
| **EP-04** | 필수정보 | 이름과 주민등록번호를 필수정보로 관리한다. 생년월일과 성별은 주민등록번호에서 산출한다. |
| **EP-05** | 동일 수검자 및 중복등록 | 주민등록번호를 동일 수검자 판단의 고유 식별정보로 사용한다. 주민등록번호가 동일하면 동일 수검자로 판단하고 신규 중복등록을 허용하지 않는다. |
| **EP-06** | 식별정보 불일치 | 동일 주민등록번호의 기존 수검자가 있으나 이름이 다르면 신규 등록하지 않고 기존 수검자 정보를 확인한다. 확인 후 기존 PatientId를 사용한다. |
| **EP-07** | 중복 후보 | 이름+생년월일이 같고 주민등록번호가 다른 기존 수검자가 있으면 중복 후보로 표시하여 오입력 여부를 확인한다. 주민등록번호가 실제로 다르면 별도 수검자로 등록할 수 있다. |
| **EP-08** | 정보 수정 및 식별정보 변경 제한 | 이름·주민등록번호·차트번호 등 기본정보를 수정할 수 있다. 주민등록번호 또는 차트번호 변경 시 고유성을 다시 검증한다. 주민등록번호 변경은 해당 수검자에게 `예약(RSV)` 또는 `접수완료(RCP)` 업무가 하나라도 있으면 차단하고, 해당 업무가 없을 때만 허용한다. 주민등록번호 변경으로 기존 업무를 자동 재판정하거나 자동 취소하지 않는다. 차트번호 변경에는 활성 업무 존재 검증을 적용하지 않는다. |
| **EP-09** | 수검자 독립성 | 정상 저장된 수검자는 이후 예약이 실패·중단되어도 유지한다. |
| **EP-10** | 삭제 범위 | 수검자 Master 삭제는 지원하지 않는다. 물리삭제·논리삭제·복원 기능을 제공하지 않으며 정보 오류는 EP-08의 수정으로 처리한다. |

## 2.1 주민등록번호 과제 처리 원칙

- 과제에서는 임의 생성한 테스트 주민등록번호만 사용한다.
- 입력 시 `-`를 제거하여 숫자 13자리로 정규화한다.
- 6자리 생년월일의 실제 날짜 유효성과 7번째 자리의 세기·성별 코드를 검증한다.
- 실제 행정번호 존재 여부와 마지막 검증번호 계산은 수행하지 않는다.
- 화면 표시 위치에서는 임의 생성한 테스트 전체값을 표시할 수 있다.
- DB에는 `-`를 제거한 숫자 13자리 테스트 값을 `수검자.SocialNumber`에 저장한다.
- `SocialNumber`는 전체 수검자에서 고유해야 하며 조회·중복판정은 해당 값의 정확검색으로 수행한다.
- C#은 입력 편의를 위해 파생값을 계산할 수 있으나 저장 Stored Procedure가 형식·실제 날짜·세기·성별·고유성을 최종 검증한다.
- 실제 주민등록번호는 입력·Seed·테스트에 사용하지 않는다.

| 구분 | 당일예약 마감 | 접수 마감 |
|---|---:|---:|
| **평일 오전** | 10:00 | 11:00 |
| **평일 오후** | 15:00 | 16:00 |

적용 기준:

```text

```

- 일반 당일예약은 해당 시간대의 당일예약 마감 전까지만 가능하다.

- 접수는 해당 시간대 접수 마감 전까지만 가능하다.
- 모든 마감은 CP-04 운영시간 안에서만 적용한다.

# 4. RP 예약 정책

| ID | 구분 | 정책 |
|---|---|---|
| **RP-01** | 예약 단위 | `1예약 = 1수검자 + 1회 내원`으로 관리한다. 하나의 예약을 검사별 또는 여러 내원 일정으로 분할하지 않는다. |
| **RP-02** | 예약 일정 | 예약일은 필수다. 평일은 오전/오후, 토요일은 오전만 선택한다. 시·분 단위의 정확한 예약시간은 관리하지 않는다. |
| **RP-03** | 시간대 정원 | 예약일+시간대별 정원은 20명이다. `예약(RSV)`과 `접수완료(RCP)`는 각각 1건으로 산정하고 `취소(CNR·CNC)`는 제외한다. 정원 20명 도달 시 신규예약과 해당 시간대로의 변경을 허용하지 않는다. |
| **RP-04** | 예약일 조건 | 예약일은 CP/HOL의 업무 가능일이어야 한다. 과거일 신규예약은 허용하지 않는다. |
| **RP-05** | 당일예약 및 현장예약 | 당일예약을 허용한다. 일반 당일예약은 해당 시간대 당일예약 마감 전까지만 가능하다. 예약 없이 현장 내원한 경우 당일예약 마감 전에는 일반 당일예약으로, 당일예약 마감 이후부터 접수 마감 전까지는 `WalkIn` Context의 현장 당일예약으로 먼저 예약을 생성한 후 접수한다. 현장 당일예약도 정원·중복·TGT·NEX·AEX·HOL 등 나머지 신규예약 조건을 모두 만족해야 하며 접수 마감부터는 허용하지 않는다. |
| **RP-06** | 중복예약 | 동일 수검자는 동시에 둘 이상의 중복판단 유효예약을 가질 수 없다. 중복판단 유효예약은 `예약일 >= DB 현재일`이고 상태가 `예약(RSV)` 또는 `접수완료(RCP)`인 업무다. 과거 업무는 중복판단에서 제외한다. 예약변경에서는 변경 대상 `WorkId` 자체를 제외한 다른 업무만 중복판단한다. |
| **RP-07** | 검진 대상 | 일반건강검진 대상자로 판정된 수검자만 신규예약할 수 있다. 확정 예약일을 기준으로 TGT Rule을 적용한다. |
| **RP-08** | 검사 구성 | NEX는 확정 예약일과 수검자 정보에 따라 시스템이 자동 구성하며 사용자가 변경할 수 없다. AEX는 Master/Rule을 만족하는 항목을 0개 이상 선택할 수 있다. NEX 없이 AEX만으로 예약할 수 없고, 동일 `ExamItemCode`의 NEX와 AEX를 동시에 저장할 수 없다. |
| **RP-09** | 예약 변경 | `예약(RSV)` 상태에서만 변경할 수 있다. DB 현재값과 요청값을 비교해 실제 변경항목을 판단하고 영향받는 Rule만 재검증한다. 세부 영향범위는 4.1을 따른다. |
| **RP-10** | 예약 취소 | 접수 전 `예약(RSV)` 상태만 취소할 수 있다. 동일 업무 행을 `예약취소(CNR)`로 변경하고 CP-05를 적용한다. |

## 4.1 예약 변경 영향범위

| 실제 변경 | 재검증 범위 | 처리 원칙 |
|---|---|---|
| 예약일 변경 포함 | 일정·마감·정원·중복 → TGT → NEX 재구성 → AEX 재검증 | 비대상이면 저장하지 않고 기존 예약 유지. AEX 충돌은 재선택 후 저장 |
| 시간대만 변경 | 일정·마감·정원·중복 | TGT/NEX/AEX를 읽기·재검증·재작성하지 않음 |
| AEX만 변경 | RP-08/AEX | 예약일·시간대·TGT·NEX 유지 |
| 시간대+AEX 변경 | 일정·마감·정원·중복 + AEX | TGT/NEX 유지 |
| 변경 없음 | 상태·동시성 확인 후 No-op | 불필요한 Detail 재작성 금지 |

- 변경구분 플래그를 C#이 임의 지정하는 방식에 의존하지 않는다.
- 저장 SP가 현재 데이터와 요청값을 비교하여 예약일·시간대·AEX 집합의 실제 변경 여부를 계산한다.
- 예약변경의 중복검증은 현재 `WorkId`를 제외하고 다른 `RSV/RCP` 업무만 대상으로 한다.

# 5. RCP 접수 정책

| ID | 구분 | 정책 |
|---|---|---|
| **RCP-01** | 예약 전제 | 접수는 등록된 예약 업무를 기준으로 처리한다. 예약 없는 직접접수는 지원하지 않는다. 현장 내원은 RP-05에 따라 예약을 먼저 생성한다. |
| **RCP-02** | 접수 가능조건 | 예약일과 실제 접수일이 동일한 경우만 접수할 수 있다. 과거·미래 예약과 취소 상태는 접수할 수 없다. 현재일이 업무 가능일이고 운영시간 내이며 해당 시간대 접수 마감 전이어야 한다. |
| **RCP-03** | 중복접수 | 이미 `접수완료(RCP)`인 업무는 다시 접수할 수 없다. |
| **RCP-04** | 접수 처리 | `예약(RSV)` 상태의 동일 데이터 행을 원자적으로 `접수완료(RCP)`로 변경한다. 예약일과 시간대는 그대로 유지한다. |
| **RCP-05** | 접수 변경 | `접수완료(RCP)` 상태에서는 예약일·시간대·NEX를 변경할 수 없다. AEX의 추가·제거만 허용하고 RP-08/AEX Rule을 동일하게 적용한다. |
| **RCP-06** | 접수 취소 | `접수완료(RCP)`를 취소하면 동일 업무 행을 `접수취소(CNC)`로 변경한다. 예약 상태로 되돌리지 않으며 해당 예약·접수 업무 전체가 취소된 것으로 판단한다. |

# 6. 예약·접수 상태 해석

```text
예약(RSV)
 ├─ 예약 변경 ─────────────→ 예약(RSV)
 ├─ 예약 취소 ─────────────→ 예약취소(CNR)
 └─ 접수 ─────────────────→ 접수완료(RCP)
                                │
                                ├─ AEX 변경 → 접수완료(RCP)
                                └─ 접수 취소 → 접수취소(CNC)

예약취소(CNR) · 접수취소(CNC)
 └─ 기존 건 복원 불가
    재진행은 신규 예약
```

| 상태 | 정원 산정 | 예약변경 | 예약취소 | 접수 | 접수완료 AEX 변경 | 접수취소 |
|---|:---:|:---:|:---:|:---:|:---:|:---:|
| 예약(RSV) | 1 | O | O | 조건부 O | X | X |
| 접수완료(RCP) | 1 | X | X | X | O | O |
| 예약취소(CNR) | 0 | X | X | X | X | X |
| 접수취소(CNC) | 0 | X | X | X | X | X |

허용되지 않은 역방향·순환 상태전이는 구현하지 않는다.

# 7. 세부 업무 Rule

## 7.1 TGT — 일반건강검진 대상판정 Rule

| ID | Rule |
|---|---|
| **TGT-01** | 대상판정 기준일은 예약일이다. 예약일 기준 만 20세 이상만 대상판정을 진행하고 만 20세 미만은 비대상이다. |
| **TGT-02** | 예약일보다 과거인 `일반건강검진 + 검진완료` 이력만 사용한다. 현재 예약·접수 업무의 상태(RSV/RCP/CNR/CNC)는 완료이력으로 사용하지 않는다. 예약일 당일 또는 이후 완료이력도 해당 예약의 판정에서 제외한다. |
| **TGT-03** | 만 20세 이상이고 과거 일반건강검진 완료이력이 없으면 최초 검진 대상으로 판정한다. |
| **TGT-04** | 완료이력이 있으면 예약일 이전의 가장 최근 완료연도를 사용한다. `예약연도 - 최근 완료연도 >= 2`이면 대상, 그 외 비대상이다. |
| **TGT-05** | 공단 대상자 API, 건강보험 가입유형, 직장/사무직 여부 등 실제 자격정보는 사용하지 않는다. 완료이력은 과제용 Seed/Test Data로 제공할 수 있다. |

판정식:

```text
AgeOnReservationDate >= 20
AND
(
  PriorCompletionNotExists
  OR ReservationYear - LatestPriorCompletionYear >= 2
)
```

### 7.2.2 조건부 검사오더 5종

| ID | 검사 | 생성조건 |
|---|---|---|
| **NEX-02** | 이상지질혈증 | 남성: 예약일 기준 만 24세 이상이고 `(만 나이-24) % 4 = 0`; 여성: 만 40세 이상이고 `(만 나이-40) % 4 = 0` |

| **NEX-04** | C형간염 | 예약일 기준 만 56세 |
| **NEX-05** | 골밀도검사 | 여성이고 예약일 기준 만 54세, 60세, 66세 중 하나 |
| **NEX-06** | 폐기능 | 예약일 기준 만 56세 또는 66세 |
| **NEX-07** | 공통 | NEX는 시스템이 자동 생성·재구성하며 사용자가 임의 추가·삭제할 수 없다. 모든 나이 계산은 예약일 기준으로 한다. |

- 조건부 5종은 Rule 정의 집합이며 같은 예약일·수검자에게 동시에 성립 가능한 조건부 항목은 최대 3종이다. 따라서 TGT 대상자의 실제 NEX 구성은 기본 8종과 조건부 0~3종을 합한 **8~11종**이다.
- 심뇌혈관 위험평가 및 기타 조건부 평가항목은 이번 과제의 예약·접수 검사오더 범위에서 제외한다.
- 기본 `혈액검사(EX007)`와 AEX `HbA1c(EX018)`는 별도 검사코드다.

## 7.4 HOL — 휴무일 기준 Rule

| ID | Rule |
|---|---|
| **HOL-01** | 월요일~토요일을 기본 운영요일로 하고 일요일은 항상 업무 불가로 판단한다. |
| **HOL-02** | 월~토라도 활성 휴무일 Master에 해당 날짜가 등록되어 있으면 업무 불가다. |
| **HOL-03** | 대한민국 공휴일 API 또는 외부 달력을 연계하지 않는다. 법정공휴일·대체공휴일·센터 자체 휴무일을 동일 Master로 관리하고 `휴무구분`으로 구별한다. |
| **HOL-04** | 논리 최소정보는 `휴무일 / 휴무일명 / 휴무구분 / 사용여부 / 비고`이며 동일 날짜 중복등록을 허용하지 않는다. `휴무구분`은 `법정공휴일 / 대체공휴일 / 자체휴무일` 세 값이다. |
| **HOL-05** | 자체휴무일은 휴무일 관리 화면에서 등록·수정·삭제한다. 법정공휴일·대체공휴일은 Seed Data로 제공하며 화면에서 변경하지 않는다. |
| **HOL-06** | 법정공휴일·대체공휴일 Seed는 유한한 기간만 등재한다. 등재 최종일을 넘어가면 그 뒤 공휴일을 업무 가능일로 잘못 판단하므로 만료 전 갱신은 운영 책임이며, 잔여 기간이 임계 미만이면 경고한다. |

```text
월~토 AND 활성 휴무일 아님 → 업무 가능일
일요일 OR 활성 휴무일      → 업무 불가일
```

`휴무구분`은 업무 가능일 판정에 들어가지 않는다. 판정은 `사용여부`만 읽는다.

HOL-06의 등재 범위와 경고 임계는 여기가 단일 출처다. 아래 값을 게이트가 읽어 판정한다.

```text
공휴일 Seed 등재 범위 = 2026-01-01 ~ 2027-12-31
갱신 경고 임계 = 잔여 180일
```

# 9. 최종 구현 기준

다음을 본 프로젝트의 최상위 업무 기준으로 확정한다.

1. CP-01~06, EP-01~10, RP-01~10, RCP-01~06을 적용한다.
2. TGT-01~05, NEX-01~07, AEX-01~05, HOL-01~06을 적용한다.
3. 신규예약은 `예약일·시간대 확정 → 일정검증 → TGT → NEX → AEX → 저장` 순서다.
4. 예약일 변경은 일정검증 후 TGT/NEX/AEX를 영향 재검증한다.
5. 시간대만 변경하면 TGT/NEX/AEX를 재검증하지 않는다.
6. 예약과 접수는 동일 업무 행의 상태전이로 관리한다.
7. 직접접수는 없으며 현장 내원도 당일예약을 먼저 생성한다.
8. 취소 건은 보존·조회하고 복원하지 않는다.
9. UI 검증은 사용자 안내이며 데이터 변경의 최종 권한은 Stored Procedure/Transaction에 둔다.
10. 주민등록번호는 임의 생성한 테스트 값 13자리만 사용하며 저장 SP가 형식·파생값·고유성을 최종 검증한다.
11. 후속 Phase는 본 정책을 구체화할 수 있으나 본 문서의 업무 의미·수치·범위를 변경할 수 없다.
