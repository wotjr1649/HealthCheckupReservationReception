## 4. 시간대 줄의 잔여 — 「예약 후」에서 「예약 전」으로 (사용자 지시)

```text
전   오전  1 / 20 (예약 후 잔여 18)     ← 앞의 두 수와 하나 어긋나 보인다
후   오전  1 / 20 (예약 전 잔여 19)
```

`clsWorkText.FormatCapacityAfterBooking` 이 `FormatCapacityBeforeBooking(현재인원, 정원)`
으로 바뀌었다. **DB 의 `잔여자리` 를 더 이상 쓰지 않는다** — `SP-RSV-01` RS2 의 그 값은
`MAX(0, 정원 - 적용후인원)` 이고 신규는 `적용후인원 = 현재인원 + 1` 이라(05 §9.7) 앞의 두
수와 기준이 다르다. 같은 계약이 준 `정원`·`현재인원` 의 차이로 적으므로 규칙이 화면으로
새지 않고, `MAX(0, ...)` 의 바닥만 따라간다.

`03` 은 이 문구를 규정하지 않는다 — §8.3 에 잔여 표기가 없다. 확인하고 바꿨다.

## 6. 예약 변경 모달이 통째로 비어 있었다 — 2026-09-12 사용자 보고

캡처에서 시간대·대상판정·NEX·AEX 가 전부 빈 채로 떴고 저장도 꺼져 있었다. **화면 탓이
아니라 SP 가 주지 않은 것을 화면이 「없음」으로 읽은 것**이다.

실측(D0003 의 실제 행으로 SP 를 화면과 똑같이 호출):

```text
A  현재 예약일 + 현재 시간대 + AEX 전부 0   → 변경범위 NONE,  RS2~RS5 전부 0행, 저장가능 0
B  AEX 하나만 켜서                          → 변경범위 EXTRA, RS5 7행 도착,     저장가능 1
```

**「일정은 그대로, 추가검사만 변경」은 계약에 있다** — 그게 `EXTRA` 이고 B 에서 저장가능이
실제로 1 이 된다. 못 했던 이유는 규칙이 아니라 **AEX 목록이 화면에 없어 체크할 대상이
없었기 때문**이다. 닭과 달걀이었다.

### 고친 것 넷

```text
1  BeginChange(detail) → BeginChange(workId)
   모달이 SP-WRK-02 로 상세를 스스로 읽는다 (DLG-RCP-01·02 와 같은 방식).
   NEX(RS2)·추가검사구성 7행(RS5)·정원(RS1)·최신 행버전을 한 번에 받는다

2  Render 가 0행을 「유지」로 읽는다 (03 §10.3 「TGT/NEX/AEX 유지」)
   무엇을 재평가했는지는 RS1 의 예약일변경여부·시간대변경여부·추가검사변경여부 셋이
   말한다 — **변경범위 문자열을 C# 에 옮겨 적지 않았다** (ROOT AGENTS.md §6).
   신규예약은 셋 다 NULL 이고 늘 ALL 이다

3  시간대 두 줄을 진입에서 세운다 (05 §9.7 「AM/PM 정확히 2행」)
   이름은 이미 있던 clsWorkText.FormatSlot 이 준다 — 새 상수도 새 게이트도 만들지 않았다.
   지금 시간대의 정원은 RS1 이 주고 반대쪽은 정원 0(=모름)이라 화면이 이름만 적는다.
   고르는 순간 시간대변경여부=1 이 되어 SP 가 두 행의 정원을 함께 준다

4  저장을 변경 모드에서 열어 둔다 (03 §10.3 이 준 「No-op 안내」 쪽)
   `[!]` AEX 체크는 SP 를 다시 부르지 않는다(Ask 의 판단 — 클릭마다 동기 SP 를 부르면
        화면이 얼어붙는다). 그래서 저장가능이 진입 때의 0 에 머물고, 버튼을 그 값에만
        매어 두면 **골라도 누를 수가 없다.** 이것이 없으면 1~3 을 다 해도 기능이 안 된다.
   판정을 화면이 대신하지 않는다 — 차단코드가 있으면 그대로 닫고, 없을 때만 연다.
   실제 판정은 SP-RSV-03 이 저장 시점에 하고 바꾼 것이 없으면 결과코드=1 을 돌려준다.
   그때는 Workbench 로 넘기지 않고 사유를 적고 창을 열어 둔다 (05 §11.2)
```

`[X]` **`_slots` 에 지어낸 값을 넣지 않았다.** 그것은 `마감시각` 으로 「오늘인가」를 가르는
자리다(`IsToday`). 진입에서 세우는 두 줄에는 담을 마감시각이 없으므로 화면 표시에만 쓴다.

### 남은 것 하나 — 범위 밖으로 둔다

변경 모드에서 예약일을 바꾸지 않으면 `_slots` 가 끝까지 비어 있으므로, 오늘 건의 AEX 만
바꿔 저장해도 착지가 **접수 Workbench 가 아니라 예약 Workbench** 다. 고치려면 DB 오늘날짜를
따로 물어야 하고(PC 시계는 쓰지 않는다), 그것은 SP 왕복을 늘리는 방향이라 이번 지시의
셋에 없다. 지시를 받으면 그때 한다.
