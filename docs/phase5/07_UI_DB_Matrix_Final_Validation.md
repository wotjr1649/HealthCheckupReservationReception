### 3.6.1 Ribbon 활성화의 출처는 RS4 다 `[B]`

`03` §9.6·§9.7·§14.3 이 상태별 Action 표를 준다. `05` §8.2 RS4 `가능한업무` 가 **같은 판정을
5행으로 돌려준다** — `EDIT_RESERVATION` · `CANCEL_RESERVATION` · `START_RECEPTION` ·
`EDIT_EXTRA` · `CANCEL_RECEPTION`.

**둘이 같은 값을 두 곳에서 계산하는 구조다.** 그러므로 화면은 RS4 를 그린다.

```text
허용여부  → BarButtonItem.Enabled
사유코드  → Disabled 사유 표시 (03 §15.1 "미리 판단 가능한 선택불가 → Disabled + 사유")
```

`[I]` C# 이 상태코드로 Enabled 를 **다시 계산하지 않는다.** RS4 는 상태뿐 아니라 현재
업무일·운영시간·접수마감·예약일까지 함께 본다(`05` §8.2 차단 우선순위). 화면이 그 넷을 다시
판정하면 DB 와 어긋나는 순간이 생기고, 어긋나는 쪽은 언제나 화면이다.

`[B]` **`[변경이력]` 은 RS4 에 없다.** 조회 Action 이라 상태·업무불가와 무관하게 행이 선택되면
열린다 (`03` §9.6, §23.4). 행 미선택일 때만 Disabled 다.

`[B]` **`[현장 당일예약]` 도 RS4 에 없다.** 선택행과 무관한 독립 Action 이다 (`03` §9.7).
다만 공통 업무불가에서는 Disabled 다 — `03` §9.7 표의 마지막 행.

### 3.6.2 Targeted Navigation 은 `SP-WRK-02` 하나로 끝난다 `[I]`

`03` §9.1 은 *"조회조건과 무관하게 `WorkId` 직접조회"* 를 요구한다.
`SP-WRK-01` 에는 **`@업무ID` Parameter 가 없다** (`05` §8.1) — 이 요구를 목록 SP 로는 만들 수 없다.

`SP-WRK-02` RS1 이 Grid 기본 컬럼(`예약일`·`시간대코드`·`상태명`·`성명`·`차트번호`)과
선택 컬럼(`성별`·`생년월일`·`휴대전화`)을 **모두 포함한다** (`05` §8.2). 그러므로


`[A]` **`03` 도 `05` 도 이 결선을 명시하지 않았다.** 가장 작은 되돌릴 수 있는 해석을 택했다 —
새 SP 도, 조회조건 변조도 필요 없고 계약 안에서 닫힌다. §14 `A-02`.
