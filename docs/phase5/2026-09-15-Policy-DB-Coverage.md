# 정책 ↔ DB 검증 대조 — `00` 의 규칙 55개는 무엇이 재는가

## 왜 이 문서가 있나

`00_Project_Policy.md` 가 규칙 **55개**를 이름으로 세운다(`CP`·`EP`·`RP`·`RCP`·`TGT`·`NEX`
·`AEX`·`HOL`). 그런데 그 이름으로 `database/tests/*.sql` 을 찾으면 **42개가 한 번도 나오지
않는다.**

`[!]` **안 재진다는 뜻이 아니었다 — 추적할 수 없다는 뜻이었다.** DB 시험은 규칙 이름이 아니라
**결과코드와 동작**으로 적혀 있다. 2026-09-15 에 그 42개를 하나씩 동작으로 찾아 맞췄고, 이
문서가 그 다리다. 다음 사람이 「`AEX-03` 은 누가 재나」를 물으면 여기서 답이 나온다.

## 이 문서가 보증하는 것과 하지 않는 것

```text
보증한다      00 의 규칙 ID 전건이 이 표에 한 줄씩 있다 — verify-policy-coverage.js 가 잰다
보증하지 않는다  그 줄에 적힌 시험이 정말 그 규칙을 재는지. 그것은 사람이 읽어 판단한 것이고
              2026-09-15 의 판단이다. 시험이 바뀌면 이 표가 뒤처진다
```

`[X]` **게이트를 여기까지만 둔 것은 의도다.** 「이 시험이 이 규칙을 잰다」를 기계가 판정하려면
시험마다 규칙 ID 를 적어야 하고, 그러면 값이 두 곳이 된다(ROOT `AGENTS.md` §6). 대신 **규칙이
늘거나 이름이 바뀌면 red** 가 되게 해서, 표가 조용히 낡는 것만 막는다.

## 2026-09-15 실행 결과

`database/scripts/test.sh` 를 운영시간 안에서 돌렸다 — rebuild · 스키마 · Seed · Rule ·
SELECT · 쓰기 · 계약 · 동시성 · 음성시험 · clean-rebuild **FAIL 0 · SKIP 0 · NOT RUN 1**.
