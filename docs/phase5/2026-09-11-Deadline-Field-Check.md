# 마감시각 규칙(03 §8.6)의 화면 실측 — 쪼리와 기록

- **왜 있나:** `§4.8`(session-17)이 개발 중 운영기준 창을 넓혀 두었고, 그래서 **마감시각
  규칙이 화면 끝까지 통한 채로 한 번도 실측되지 않았다.** R19 회귀가 창을 `00` 값으로
  되돌렸으므로 이제 잴 수 있다
- **DB 쪽은 이미 판정된다** — `OFF-308-01`·`OFF-309-02`·`RUL-T02`·`T03` 이 회귀에서 돈다.
  여기서 재는 것은 **화면이 그 코드를 받아 무엇을 하는가** 다
- **채우는 문서:** 결과는 이 파일에 적는다. `07` 이 아니다 (ROOT `AGENTS.md` §4 가 07 의
  갱신 의무를 면제했다)
- **선행:** `2026-09-10-session-17-Phase5-UI-Overhaul.md` §4.8 · §4.9

`[!]` **운영기준을 다시 넓히지 마라.** 넓히는 순간 이 문서는 아무것도 재지 못한다.

## 1. 창 — 무엇을 언제 볼 수 있나

`[!]` **시각값을 여기 적지 않는다.** 소유자는 `00` CP-04 와 §3 마감표이고 실물은
`dbo.운영기준` 한 행이다 (R13). `verify-operating-baseline.sh` `OPR-G1~G4` 가 셋의 일치를
매 회귀에서 판정하는데 **그 게이트도 `verify-docs` `V26` 도 이 문서는 보지 않는다** —
여기에 숫자를 베끼면 게이트 없는 사본이 되고, 그것이 ROOT `AGENTS.md` §6 이 막는 바로 그
형태다. 앉기 전에 **살아 있는 값을 찍어라**:

```bash
cd database
sqlcmd -S '.\SQLEXPRESS' -E -d HealthCheckupReservationReceptionDb -b -I -W -s'|' -Q "
SELECT 운영시작시각, 운영종료시각, 일반예약AM마감, 일반예약PM마감, 접수AM마감, 접수PM마감,
       CONVERT(TIME(0), SYSDATETIME()) AS 지금 FROM dbo.운영기준 WHERE 기준ID=1;"
```

찍은 값을 아래 경계에 대입해 읽는다. 경계 이름만 쓰므로 값이 바뀌어도 이 표는 안 썩는다.

```text
지금이 어디인가                       Normal   WalkIn   볼 수 있는 것
운영시작 ~ 일반AM마감        AM       가능     가능     일반 당일예약 성공 (전환 없음)
일반AM마감 ~ 접수AM마감      AM       304      가능     **304 → 현장 전환 성공** (AM 창)
접수AM마감 ~ 일반PM마감      PM       가능     가능     일반 당일예약 성공 (PM)
일반PM마감 ~ 접수PM마감      PM       304      가능     **304 → 현장 전환 성공** (PM 창) ← 핵심
접수PM마감 ~ 운영종료        둘 다    304      304      당일예약 전부 막힘 · 접수도 막힘
운영종료 이후                 —        309      309      운영시간 밖
휴무일 · 일요일                        308      308      센터 닫힘
```

토요일은 PM 자체가 불가다 (`03` §8.6). 실측은 평일에 한다.

**결과코드도 여기 정의하지 않는다** — `Common/DbCode.cs` 가 갖고 `verify-dbcode.sh` 가 `05`
§16.1 과 대조한다. 이 문서가 부르는 이름은 `CutoffPassed`(304) · `CenterClosed`(308) ·
`OutsideHours`(309) · `NotToday`(503) 다.

## 2. 화면이 하는 일 — 무엇을 기대하는가

`ReservationPresenter` 가 `00` RP-05 를 이렇게 구현한다 (조작자에게 시계를 읽히지 않는다):

```text
1  Normal 로 SP-RSV-01 조회
2  돌아온 시간대 중 **하나라도** BlockCode = 304 면
3  WalkIn 으로 한 번 더 조회하고 그 결과를 그린다 · 예약구분 = 현장 당일예약
```

`[!]` **오늘인지를 화면이 재지 않는다.** `03_Functions.sql` 이 `적용마감시각 = CASE WHEN
@예약일 = 오늘날짜 THEN 기본마감시각 ELSE NULL END` 이므로 **마감이 걸렸다는 것 자체가
그 날이 DB 오늘날짜라는 뜻**이다. PC 시계를 보지 않는다 — 창구 PC 가 하루 어긋나도 안전하다.

## 3. 시나리오

### S1 — 당일예약 전부 막힘 (접수PM마감 ~ 운영종료. 오늘 가능)

```text
조작   수검자 관리에서 유효업무 없는 사람 하나를 골라 [예약] · 예약일 = 오늘
기대   AM·PM 둘 다 선택 불가 · 사유가 마감경과로 보인다
       예약구분 표시가 무엇인지 **관찰만 한다** (§4 가설 H1 이 여기 걸린다)
후확인 화면이 저장을 시도하지 않았으므로 DB 는 그대로다
```

### S2 — 접수 마감 경과 차단 (접수PM마감 ~ 운영종료. 오늘 가능)

```text
조작   접수 관리 탭 (오늘 ~ 오늘로 자동 조회된다) → RSV 행 하나 → [접수]
기대   막힌다. 화면이 이유를 말한다
후확인 SELECT 상태코드 FROM dbo.예약접수 WHERE 업무ID = <그 행>   →  RSV 그대로
```

### S3 — 운영시간 밖 (운영종료 이후. 오늘 가능)

```text
조작   프로그램을 새로 띄운다 · 수검자 관리 [조회] · 아무 행에서 [예약]
기대   업무 불가가 화면에 뜬다 (309). 리본 Action 이 닫힌다
       **닫히는 것과 「모르는 것을 불가로 적는 것」은 다르다** — 조회가 성공했고 DB 가
       309 를 냈으므로 닫히는 것이 맞다
후확인 없음 (읽기만)
```

### S4 — 304 → 현장 전환 **성공** (월요일, 일반PM마감 ~ 접수PM마감) ← 핵심

```text
조작   유효업무 없는 사람 하나 → [예약] · 예약일 = 오늘 · PM 선택
기대   AM 은 마감으로 막히고 PM 은 고를 수 있다
       예약구분 = **현장 당일예약**
       저장 성공
후확인 SELECT 예약구분, 시간대코드, 상태코드 FROM dbo.예약접수 WHERE 업무ID = <새 행>
       →  WALKIN · PM · RSV
```

### S5 — 304 → 현장 전환, AM 창 (월요일, 일반AM마감 ~ 접수AM마감. 여유 있으면)

```text
조작   같은 조작, 예약일 = 오늘, **PM 을 고른다**
기대   여기서 H1 이 드러난다 — 아래 §4 를 보고 관찰한다
```

## 4. 가설 — 확인해야 할 것

### H1 `[미확인]` AM 이 마감이면 PM 도 현장으로 넘어가는가

`CutoffBlocked` 가 *시간대 중 **하나라도** 304 면* 전환한다. 그런데 마감은 시간대마다
다른 값이다 — 일반예약 AM 마감과 PM 마감이 다르다.

```text
AM 창(일반AM마감 지남 · 접수AM마감 전)에 **PM 을** 예약하려는 사람
  PM 일반마감은 아직 안 지났으므로 00 RP-05 대로면 **일반 당일예약**이어야 한다
  그런데 AM 이 304 라는 이유로 화면이 WalkIn 으로 바꾼다 → WALKIN 으로 저장될 수 있다
```

**막히지는 않으므로 조작자는 모른다.** 틀린다면 저장된 `예약구분` 이 사실과 달라지는
데이터 정확성 문제다. `S5` 가 이것을 본다.

`[!]` **이것은 실측 없이도 잴 수 있다** — Fake 로 `AM=304 차단 · PM=선택가능` 을 물려
`_reserveType` 이 무엇이 되는지 보는 단위시험이면 결정적으로 판정된다. 월요일을 기다릴
필요가 없고, 그쪽이 더 정확하다. 실측은 그 결론을 실행본에서 한 번 확인하는 몫이다.

## 5. 점검용 데이타

오늘자 행은 **SP 를 거치지 않고 직접 `INSERT`** 했다 — 그래야 실측 대상인 마감 규칙을
건드리지 않는다. 하네스 fixture(`T0xx`)는 계약시험이 쓰므로 손대지 않았고 차트번호 `D%` 로
새로 만들었다.

```sql
-- 심은 것: 오늘 AM RSV 4 · RCP 3 / PM RSV 2 · RCP 1 · 수검자 D0001~D0010
-- 되돌리기
DELETE w FROM dbo.예약접수 w JOIN dbo.수검자 p ON p.수검자ID = w.수검자ID
WHERE p.차트번호 LIKE 'D%';
DELETE FROM dbo.수검자 WHERE 차트번호 LIKE 'D%';
```

`[!]` **유효업무 없는 수검자를 남겨 두어야 한다.** `00` RP-06 이 유효업무 1건을 강제하므로
전원에게 오늘 예약을 주면 `S4`·`S5` 에서 예약을 만들 대상이 `306`/`701` 로 전부 막힌다.
심은 직후 실측: **19명**이 비어 있다.

```sql
SELECT COUNT(*) FROM dbo.수검자 p
WHERE NOT EXISTS (SELECT 1 FROM dbo.예약접수 w WHERE w.수검자ID = p.수검자ID
                  AND w.상태코드 IN ('RSV','RCP') AND w.예약일 >= CAST(GETDATE() AS DATE));
```

회귀(`database/scripts/test.sh`)를 돌리면 `DROP DATABASE` 로 전부 사라진다. 다시 심으려면
위 조건을 만족하도록 다시 만든다.
