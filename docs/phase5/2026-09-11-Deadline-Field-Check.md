## 1. 창 — 무엇을 언제 볼 수 있나

매 회귀에서 판정하는데 **그 게이트도 `verify-docs` `V26` 도 이 문서는 보지 않는다** —
여기에 숫자를 베끼면 게이트 없는 사본이 되고, 그것이 ROOT `AGENTS.md` §6 이 막는 바로 그

```bash
cd database

SELECT 운영시작시각, 운영종료시각, 일반예약AM마감, 일반예약PM마감, 접수AM마감, 접수PM마감,
       CONVERT(TIME(0), SYSDATETIME()) AS 지금 FROM dbo.운영기준 WHERE 기준ID=1;"
```

찍은 값을 아래 경계에 대입해 읽는다. 경계 이름만 쓰므로 값이 바뀌어도 이 표는 안 썩는다.

`[X]` **화면의 전환은 시간대별이 아니라 대화상자 전체다.** `CutoffBlocked` 가
*시간대 중 하나라도 304* 면 참이고, Normal 조회에서 AM 은 일반AM마감만 지나면 304 다.
그래서 **일반AM마감을 넘긴 순간부터 운영종료까지 예약 대화상자는 언제나 현장 당일예약으로
전환한다.** 그것이 맞는 구간과 틀린 구간이 아래에서 갈린다 (§4).

```text
지금이 어디인가              고르는  Normal  WalkIn  화면이 하는 일        예약구분이 맞나
운영시작 ~ 일반AM마감        AM·PM   가능    가능    전환 없음 · 일반       맞다
일반AM마감 ~ 접수AM마감      AM      304     가능    전환 → 현장           맞다
                             PM      가능    가능    전환 → 현장           **틀렸다** (§4)
접수AM마감 ~ 일반PM마감      AM      304     304     전환 → 고를 수 없다    맞다
                             PM      가능    가능    전환 → 현장           **틀렸다** (§4)
일반PM마감 ~ 접수PM마감      PM      304     가능    전환 → 현장           맞다  ← 핵심
접수PM마감 ~ 운영종료        둘 다   304     304     전환 → 고를 수 없다    맞다
운영종료 이후                 —      309     309     업무 불가
휴무일 · 일요일                      308     308     센터 닫힘
```

토요일은 PM 자체가 불가다 (`03` §8.6). 실측은 평일에 한다.

**결과코드도 여기 정의하지 않는다** — `Common/DbCode.cs` 가 갖고 `verify-dbcode.sh` 가 `05`
§16.1 과 대조한다. 이 문서가 부르는 이름은 `CutoffPassed`(304) · `CenterClosed`(308) ·
`OutsideHours`(309) · `NotToday`(503) 다.

## 2. 화면이 하는 일 — 무엇을 기대하는가

`ReservationPresenter` 가 `00` RP-05 를 이렇게 구현한다 (조작자에게 시계를 읽히지 않는다):

```text
1  Normal 로 SP-RSV-01 조회
2  돌아온 시간대 중 **하나라도** BlockCode = 304 면
3  WalkIn 으로 한 번 더 조회하고 그 결과를 그린다 · 예약구분 = 현장 당일예약
```

`[!]` **오늘인지를 화면이 재지 않는다.** `03_Functions.sql` 이 `적용마감시각 = CASE WHEN
@예약일 = 오늘날짜 THEN 기본마감시각 ELSE NULL END` 이므로 **마감이 걸렸다는 것 자체가
그 날이 DB 오늘날짜라는 뜻**이다. PC 시계를 보지 않는다 — 창구 PC 가 하루 어긋나도 안전하다.

## 3. 시나리오

### S1 — 당일예약 전부 막힘 (접수PM마감 ~ 운영종료. 오늘 가능)

```text
조작   수검자 관리에서 유효업무 없는 사람 하나를 골라 [예약] · 예약일 = 오늘
기대   AM·PM 둘 다 선택 불가 · 사유가 마감경과로 보인다
       예약구분 표시가 무엇인지 **관찰만 한다** (§4 의 H1 이 여기서도 보인다)
후확인 화면이 저장을 시도하지 않았으므로 DB 는 그대로다
```

### S2 — 접수 마감 경과 차단 (접수PM마감 ~ 운영종료. 오늘 가능)

```text
조작   접수 관리 탭 (오늘 ~ 오늘로 자동 조회된다) → RSV 행 하나 → [접수]
기대   막힌다. 화면이 이유를 말한다
후확인 SELECT 상태코드 FROM dbo.예약접수 WHERE 업무ID = <그 행>   →  RSV 그대로
```

### S3 — 운영시간 밖 (운영종료 이후. 오늘 가능)

```text
조작   프로그램을 새로 띄운다 · 수검자 관리 [조회] · 아무 행에서 [예약]
기대   업무 불가가 화면에 뜬다 (309). 리본 Action 이 닫힌다
       **닫히는 것과 「모르는 것을 불가로 적는 것」은 다르다** — 조회가 성공했고 DB 가
       309 를 냈으므로 닫히는 것이 맞다
후확인 없음 (읽기만)
```

### S4 — 304 → 현장 전환 **성공** (월요일, 일반PM마감 ~ 접수PM마감) ← 핵심

```text
조작   유효업무 없는 사람 하나 → [예약] · 예약일 = 오늘 · PM 선택
기대   AM 은 마감으로 막히고 PM 은 고를 수 있다
       예약구분 = **현장 당일예약**
       저장 성공
후확인 SELECT 예약구분, 시간대코드, 상태코드 FROM dbo.예약접수 WHERE 업무ID = <새 행>
       →  WALKIN · PM · RSV
```

### S5 — H1 을 눈으로 확인 (평일, 일반AM마감 ~ 일반PM마감 사이 아무 때나)

`[!]` **창이 넓어서 싸다.** §4 가 확정한 대로 전환은 일반AM마감만 넘기면 일어나므로,
`S4` 처럼 한 시간짜리 창을 노릴 필요가 없다. 점심때든 오후 두 시든 상관없다.

```text
조작   유효업무 없는 사람 하나 → [예약] · 예약일 = 오늘 · **PM 을 고른다**
기대   예약구분이 **현장 당일예약** 으로 보인다 (PM 일반마감은 아직 안 지났는데도)
       저장하면 성공한다 — 막히지 않는 것이 이 결함의 성질이다
후확인 SELECT 예약구분 FROM dbo.예약접수 WHERE 업무ID = <새 행>   →  WALKIN (NORMAL 이어야 한다)
정리   확인했으면 그 행을 지운다 — 틀린 구분이 남으면 다음 사람이 데이터로 오해한다
```

## 4. H1 — **확정된 결함**. 가설이 아니다

### AM 이 마감이면, 아직 마감 전인 PM 까지 현장 당일예약으로 저장된다

2026-09-11 확인. 실측과 소스 넷이 한 줄로 이어진다 — 월요일을 기다릴 것도 없었다.

```text
1  마감은 시간대마다 다른 값이다          database/deploy/03_Functions.sql  기본마감시각 CASE
   2026-09-11 16:20 실측 — SP-RSV-01 RS2 가 AM·PM 두 행을 각자의 마감시각으로 준다
   (그때 찍힌 값은 배포 기준값과 같았다. 이 줄은 **관측 기록**이지 정책 사본이 아니다)
2  화면은 "하나라도 304 면" 전환한다       ReservationPresenter.cs  CutoffBlocked
3  전환하면 대화상자 전체가 WALKIN 이다    같은 파일, Normal 조회 직후의 재질의
4  저장 SP 는 되잡지 않는다                06_Procedures_Reservation_Write.sql
   WALKIN 은 "예약일 = 오늘날짜" 만 본다   마감구분을 RECEPTION 으로 넓혀 통과시킨다
```

```text
CutoffBlocked = (AM 이 304) OR (PM 이 304) = 현재시각 >= 일반AM마감
  그러므로 전환은 일반AM마감을 넘긴 순간부터 운영종료까지 **항상** 일어난다

틀리는 구간 = 일반AM마감 ~ 일반PM마감 에 **PM** 을 예약할 때
  PM 일반마감은 아직 안 지났으므로 00 RP-05 대로면 일반 당일예약이어야 한다
  그런데 AM 이 304 라는 이유로 화면이 WALKIN 으로 바꾸고, SP 가 그대로 저장한다
```

`[X]` **이 창은 좁지 않다.** `CutoffBlocked` 는 AM 하나만 보고 참이 되는데 AM 의 마감이
가장 이르므로, 창은 **일반AM마감에서 열려 일반PM마감까지** 간다 — 배포값이라면 운영시간의
절반이 넘는다. 초판에서 이것을 「AM 창」(일반AM마감 ~ 접수AM마감)이라 좁게 적었던 것은
**틀렸다.** 시각값은 §1 의 질의로 찍어 대입하라 (여기에 숫자를 베끼지 않는 이유도 §1 이다).

`[X]` **막히지 않으므로 조용하다.** 화면은 `현장 당일예약` 이라고 **표시까지** 하지만
조작자에게는 그것이 틀렸다는 단서가 없다. 남는 것은 사실과 다른 `예약구분` 이고, 현장
당일예약 건수를 세는 순간 부풀려진다. 오전에 와서 오후 검진을 잡는 것은 드문 조작이 아니다.

**고치는 자리는 `CutoffBlocked` 의 범위다.** 다만 시간대를 아직 고르지 않은 상태에서도
물어야 하므로(`05` §9.6 이 DB 가 하나를 정해 돌려준다) 단순히 "고른 시간대만 본다" 로
좁히면 최초 조회가 무엇을 기준으로 전환할지 정해야 한다 — **설계가 필요하고, 지시 대상이다.**

`S5` 는 이제 확인용이다. 실행본에서 한 번 눈으로 보는 것 이상은 아니다.

## 5. 점검용 데이타

오늘자 행은 **SP 를 거치지 않고 직접 `INSERT`** 했다 — 그래야 실측 대상인 마감 규칙을
건드리지 않는다. 하네스 fixture(`T0xx`)는 계약시험이 쓰므로 손대지 않았고 차트번호 `D%` 로
새로 만들었다.

```sql
-- 심은 것: 오늘 AM RSV 4 · RCP 3 / PM RSV 2 · RCP 1 · 수검자 D0001~D0010
-- 되돌리기
DELETE w FROM dbo.예약접수 w JOIN dbo.수검자 p ON p.수검자ID = w.수검자ID
WHERE p.차트번호 LIKE 'D%';
DELETE FROM dbo.수검자 WHERE 차트번호 LIKE 'D%';
```

`[!]` **유효업무 없는 수검자를 남겨 두어야 한다.** `00` RP-06 이 유효업무 1건을 강제하므로
전원에게 오늘 예약을 주면 `S4`·`S5` 에서 예약을 만들 대상이 `306`/`701` 로 전부 막힌다.
심은 직후 실측: **19명**이 비어 있다.

```sql
SELECT COUNT(*) FROM dbo.수검자 p
WHERE NOT EXISTS (SELECT 1 FROM dbo.예약접수 w WHERE w.수검자ID = p.수검자ID
                  AND w.상태코드 IN ('RSV','RCP') AND w.예약일 >= CAST(GETDATE() AS DATE));
```

회귀(`database/scripts/test.sh`)를 돌리면 `DROP DATABASE` 로 전부 사라진다. 다시 심으려면
위 조건을 만족하도록 다시 만든다.
