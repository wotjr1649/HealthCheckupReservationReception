## 2. R13 이 무엇을 바꿨나

`HC-RSV-RCP-20260910-R13` 이 `04`·`05`·`06` 셋을 열었다. 한 줄로:

> **운영시간과 마감시각 넷은 SP 본문의 리터럴이 아니라 기준정보 테이블 `운영기준` 의 1행이다.**

`[!]` **정책은 한 글자도 안 바뀌었다.** `00` CP-04 의 `09:00~18:00` 도, `00` §3장의 마감 넷도
그대로다. 바뀐 것은 **SP 가 그 값을 읽는 경로**뿐이다. 값의 소유자는 여전히 `00` 이다.

```text
04 §4.1·§7·§8.7   테이블 운영기준 (7컬럼 · PK · SINGLETON · HOURS · 감사컬럼 없음)
05 §2.4·§6.1.4·§7.1  값이 아니라 **어디서 읽는지**를 적는다
06 §14a           새 Seed 한 행. 값을 여기 적지 않고 게이트를 가리킨다
06 §33.2a         「업무시간 분기」가 「업무일 분기」가 됐다 — 시각 축이 사라졌다
06 §42 · §43      회차 R13 · 한계 1·12·14 해소 · 21 에 근거를 붙였다
```

### 2.1 왜 이것이 "설정" 이 아닌가 — 가드레일 셋

`06` §43-21 이 정원 20 에 대해 *"설정 테이블은 오히려 기준선 위반"* 이라고 적어 두었다.
그 기준을 이 값이 어떻게 지나는지가 이 회차의 승인 조건이었다 (사용자, 2026-09-09).

```text
① 관리 CRUD SP 를 만들지 않는다   05 §1.3 의 SP 목록에 없다 · UIDB-002 가 본다
                                   → 00 §8.2 밖을 그대로 유지한다. 화면에서 못 바꾼다
② 게이트가 Seed == 00 을 판정한다  verify-operating-baseline.sh OPR-G1~G3
③ 게이트가 회차 끝 복원을 판정한다  OPR-G4 — test.sh 가 회차 안에서 두 번 묻는다
```

`[X]` **셋째가 이 회차가 새로 만든 실패 방식이다.** 시험이 창을 넓혔다 되돌리지 않으면 다음
회차가 **다른 제품을 시험한 PASS** 를 낸다. `06` §43-14 가 배포 원본 수정을 금지한 이유가 그것인데,
다른 점은 이쪽엔 그것을 보는 눈이 있다는 것뿐이다.

```bash
cd database && ./scripts/verify-operating-baseline.sh          # 실물 판정
cd database && ./scripts/verify-operating-baseline.sh selftest # 변조를 잡는지 자체시험
```

### 2.2 시험이 시계를 기다리지 않는다

`OFF-308-01` 이 오늘을 휴무일로 **심어서** `308` 을 결정적으로 만든 방식을 나머지에 폈다.

```text
tests/06·07·08   창을 넓혔다 되돌린다. 남은 갈림은 요일·휴무일뿐이다
CWR-006 · 009    마감을 옮겨 성공 경로와 마감경과 경로가 둘 다 언제나 성립한다
OFF-309-02       창을 '지금이 아닌 1초' 로 좁힌다 — 오전이면 23:00:00~23:00:01,
                 오후면 11:00:00~11:00:01. 정오·자정을 넘겨도 지금을 품지 않는다
concurrency      업무시간 게이트를 걷었다. **자정 가드는 남겼다**
```

`[!]` **넓히지 않는 것 셋.** 요일과 휴무일은 `00` 이 **날짜로** 정한 것이라 대상이 아니다.
자정 가드(`23` 시)는 barrier 가 `WAITFOR TIME` 이라 하루를 넘기면 약 24시간 정지하는
**도구의 한계**이지 창이 아니다. 셋 다 `NOT RUN` 으로 남기고 `PASS` 로 쓰지 않는다.

## 3. `06` §42 창 안 회차 — 남은 것이 훨씬 작아졌다

앞 문서 §4 가 "먼저 할 일" 로 세운 항목이다. R13 회귀가 그 대부분을 가져갔다.

```text
R9  창 밖  PASS 227 · SKIP 78 · NOT RUN 9
R12 창 밖  PASS 273 · SKIP 56 · NOT RUN 9
R13 창 밖  PASS 403 · SKIP  0 · NOT RUN  1     2026-09-10 00시대 · 목
R9  창 안  PASS 399 · SKIP  2 · NOT RUN  1     ← 창 밖 회차가 이것보다 높다
```

`CON-001`~`008` 과 예약·접수 성공 경로가 **창 밖에서 판정됐다.** 남은 `NOT RUN 1` 은 `RBD-001`
하나이고 인스턴스가 1개라 구조적으로 불가능하다.

`[!]` **그래도 창 안 회차가 완전히 필요 없어진 것은 아니다.** R13 회귀는 창을 **넓힌 상태**로
성공 경로를 쟀다. 실제 `09:00~18:00` 설정 그대로 도는 회차는 아직 없다. 다만 그 회차가 더할
정보는 이제 *"진짜 창 안에서 창 판정이 0 을 낸다"* 하나로 줄었고, 그것은 `RUL-T02`·`T03`
(`09:00:00`·`17:59:59` → 가능)과 `OFF-309-02` 가 이미 잰다. **09:00~18:00 에 한 번 돌려
`06` §42 에 줄을 더하면 좋지만, R12 때처럼 막고 있는 것은 없다.**
