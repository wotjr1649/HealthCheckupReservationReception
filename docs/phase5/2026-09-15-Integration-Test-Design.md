# 통합시험 설계 — 실물이 밟지 않던 다섯

수용기준·대상·하지 않을 것·이미 밟은 함정은 `2026-09-15-session-22-Integration-Test-Design.md`
가 갖는다. **여기 베끼지 않는다**(ROOT `AGENTS.md` §6) — 이 문서는 그 기준을 **시험으로 편 것**
이고, 베껴 두면 한쪽만 고쳐지는 날이 온다.

여기 적는 것은 셋이다. 시험 다섯의 시나리오, 그 다섯이 공유하는 픽스처, 그리고 실측 결과.

## 1. 어디에 무엇이 있는가

```text
Integration/DbFixture.cs              연결문자열 한 곳 · 운영기준의 창 · 병렬 금지 검사
Integration/WriteRepositoryDbTests.cs 이번에 더한 다섯
Integration/SelectRepositoryDbTests.cs  읽기 전용. 손대지 않았다
Integration/PatientRepositoryDbTests.cs 수검자 Write 한 벌. 손대지 않았다
Integration/ScenarioDbTests.cs          S01~S07 업무 흐름. 창이 열리므로 밤에도 판정된다
```

`WriteRepositoryDbTests` 가 `SelectRepositoryDbTests` 와 자리를 나눈 이유는 그 파일 머리말이
「이 파일이 도는 동안 DB 상태가 바뀌지 않는다」고 적기 때문이다. 쓰기를 거기 넣으면 그 문장이
거짓이 된다.

## 2. 픽스처 — 운영기준의 창

**무엇이 문제인가.** 쓰기 SP 는 `09:00 <= 현재시각 < 18:00` 밖에서 `309` 로, 당일 마감
(`10:00`/`15:00`/`11:00`/`16:00`) 뒤에는 `304` 로 막힌다. 둘 다 옳은 동작이라 실패로 적을 수
없고, 그렇다고 통과로도 적을 수 없다 — **밤에 돌리면 시험이 통째로 `Inconclusive` 가 된다.**
사람이 업무시간에 맞춰 앉아 있는 것은 방법이 아니다(2026-09-14 사용자 지시).

**무엇을 하는가.** `[AssemblyInitialize]` 가 `[운영기준]` 한 행의 여섯 값을 붙들어 두고 창을
열어 둔다. `[AssemblyCleanup]` 이 붙들어 둔 값을 그대로 되돌린다. `06` §33.2a 와
`winforms/scripts/measure-cutoff.sh` 가 쓰는 같은 패턴이고, 다른 것은 **SQL 이 아니라 C# 이
한다**는 것뿐이다.

**왜 어셈블리 단위인가.** 시험마다 열고 닫으면 여는 쪽이 이미 열린 값을 「원본」으로 붙들 수
있다. 한 번만 열고 한 번만 되돌리면 그 경로가 없다. 같은 이유로 **병렬이 들어오면 안 된다** —
오늘 MSTest 는 순차이고(`Parallelize` 선언 없음), 선언은 썩으므로 그것을 잡는 시험을 픽스처에
같이 둔다.

**되돌림을 선언으로 두지 않는다.** 프로세스가 죽으면 `[AssemblyCleanup]` 도 안 돈다.
최후 방어선은 `database/scripts/verify-operating-baseline.sh` `OPR-G4` 이고, 그것이 실제로
red 를 내는 것은 2026-09-15 에 확인했다. **돌린 뒤 그것을 본다.**

`[!]` 픽스처는 `[운영기준]` 을 직접 `UPDATE` 한다. 이 테이블에는 관리 SP 가 없고(`05` §1.3),
없는 것이 의도다 — 정책 수치를 설정으로 바꾸지 않는다. 그래서 창을 옮기는 길은 직접 SQL 뿐이고,
그 한 문장을 **시험 픽스처 안에만** 둔다. 생산 코드에는 없다(`verify-layering.sh` `LAY-003`).

### 1 의 다섯 갈래

`05` §9.4 가 정한 계산을 그대로 부른다 — 무엇이 바뀌었는지 보내지 않고, **원하는 상태를
통째로 보내면 DB 가 현재 행과 견주어 변경범위를 잰다.**

| 변경범위 | 어떻게 부르는가 | RS2 | RS3 | RS4 | RS5 |
|---|---|---:|---:|---:|---:|
| `ALL` | 업무ID `NULL` — 예약이 없는 쪽 수검자로 신규예약 | 2 | 1 | 8~11 | 7 |
| `NONE` | 업무ID + 현재와 똑같은 예약일·시간대·AEX | 0 | 0 | 0 | 0 |
| `SLOT` | 시간대만 반대쪽으로 | 2 | 0 | 0 | 0 |
| `EXTRA` | AEX 하나만 켜서 | 0 | 0 | 0 | 7 |
| `SLOT_EXTRA` | 시간대 + AEX 둘 다 | 2 | 0 | 0 | 7 |

`ALL` 의 RS3·RS4·RS5 는 계약이 「0 또는 …」으로 적은 자리다(`05` §9.8~§9.10). **여기서는
0 을 허용하지 않는다** — 새로 만든 수검자이고 창이 열려 있으므로 일정 평가가 가능한 쪽이
참이어야 한다. 0 이 나오면 그것이 신호다.

`ALL` 을 **예약이 없는 다른 수검자**로 부르는 이유는 다른 유효업무가 있으면 `저장가능=0` 이
되고 RS3~RS5 가 서는지가 계약에서 갈리지 않기 때문이다. 재려는 것이 형상이므로 갈리지 않는
쪽으로 묻는다.

## 4. 씨앗 — 시험이 스스로 심는다

`scripts/seed-probe-works.sh` 를 고치지 않았다. 그것은 `measure-cutoff.sh`(SQL 계층)가 쓰는

(`seed-probe-works.sh` 머리말이 실측한 그 함정이다).

정원은 공유 자원이라 만든 것을 되돌리지 않으면 다음 실행이 `305` 로 막힌다. 그래서
`[TestCleanup]` 이 만든 업무를 상태에 맞는 취소로 되돌린다(`ScenarioDbTests` 와 같은 방식).

**시각이 중요하다.** `03:34` 는 `09:00 <= 현재시각 < 18:00` 밖이고, 이 실측 직전에

### 메우지 않은 것
