## 2. 실측 근거

### 2.1 2컬럼 형태는 허용 T-SQL 만으로 동작한다

`06` §9.2 는 `STRING_SPLIT` · XML · JSON · TVP 를 금지한다. 그래도 다음이 전부 성립한다.

```text
[1] 문자열 길이            국가검사 65자 · 추가검사 11자   NVARCHAR(100)/(50) 로 충분
[2] RS2 국가검사항목       검사코드 JOIN + 양끝 패딩 LIKE  단일 SELECT 로 11행 정확
[3] RS3 추가검사항목       같은 기법으로 2행 정확
[4] 중복판정 410·411·412   단일 식으로 판정 가능 -> 인라인 TVF 유지
[5] 7개 BIT -> 문자열      정규 순서로 생성. 집합 동일 판정이 문자열 비교 한 줄
```

펼치는 기법은 파서가 필요 없다.

```sql
FROM [dbo].[검사코드] m
WHERE ',' + w.[국가검사항목] + ',' LIKE '%,' + m.[검사항목코드] + ',%'
ORDER BY m.[검사항목코드]
```

`검사코드` 가 이미 19행을 갖고 있으므로 별도 숫자표도 `VALUES` 나열도 필요 없다.

### 2.2 `04` §5.3 의 기각 근거는 이 형태에 해당하지 않는다

> Work와 Work Exam을 합치면 예약일·상태가 검사 수만큼 중복되고 정원 COUNT가 왜곡되므로

이는 **행 방향**(검사당 1행) 이야기다. 컬럼/문자열 방향은 `예약접수` 행 수를 늘리지 않으므로
정원 산정이 그대로다. `IX_예약접수_SLOT` 도 비클러스터 인덱스라 기반 테이블 폭과 무관하다.

### 2.3 부수 효과 ― 동시성 계약이 단순해진다

`04` §4.3 은 "AEX 또는 NEX/AEX Detail 이 실제로 변경되면 같은 Transaction 에서
Work `LastEditDate` 를 갱신하여 Aggregate `RowVersion` 도 변경한다"를 요구한다.
검사가 `예약접수` 의 컬럼이 되면 **같은 행이라 자동으로 변한다.** 별도 갱신 규칙이 사라진다.
동일집합 No-op 도 문자열 비교로 자연히 판정된다.

### 2.4 변경이력 실패 기록의 소비처가 0개다

```text
읽는 Stored Procedure   0개  (04 §8.7.3 이 자인)
표시하는 화면            0개  (03_Wireframe_Definition.md 언급 0회)
판정에 쓰는 Rule         0개
```

`CP-06` 이 요구하는 "업무 결과가 확정된 호출마다"에는 정원마감·중복예약 같은 **업무 실패**가 포함된다.
그 기록을 소비하는 곳이 없으므로 성공한 데이터 변경만 남겨도 기능 손실이 없다.
`T55` 가 `CP-06` 을 그렇게 개정한다.

## 4. 결정사항

### 4.1 2컬럼 분리 (1컬럼 통합 기각)

`'EX012:NEX|EX014:AEX'` 처럼 한 컬럼에 출처를 함께 담으면 구분자가 2단이 되어
§2.1 의 단일 SELECT 기법이 깨지고 `WHILE` 파서가 필요해진다. 출처를 컬럼으로 가른다.

### 4.2 검사코드는 재설계하지 않는다

범용화(분류를 데이터로 빼는 안)는 테이블 7 -> 9, TVF 2개의 조인 1 -> 2,
`CK_검사코드_ROLE_REQUIRED` 소멸을 부른다. `00` §1.7 이 범위를 닫아 검사 19종·2분류가 확정이고,
설계서 자체 원칙(`04` §5.3)도 "필요해지면 그때 되돌린다"이다. **지금 범위로 고정한다.**

### 4.3 완료이력은 예약접수와 같은 모양

`수검자ID` · `완료일자` + 같은 2컬럼. 접수완료 업무에서 복사가 `INSERT SELECT` 한 줄이 되고,
업무ID 참조 방식과 달리 **외부 기관 검진도 같은 모양으로 담을 수 있다.**
PK 는 `(수검자ID, 완료일자)` 를 유지한다 ― 같은 날 두 번 검진은 없다.

### 4.4 완료 복사는 스크립트로만 둔다

`scripts/` 에 복사 스크립트를 두고 시나리오 시험할 때 직접 돌린다.
SP 를 신설하지 않으므로 `05` §1.3 의 외부 호출 SP 15개 계약과 `SCH-014` 기대치가 움직이지 않는다.

`[X]` **접수완료 SP 가 완료이력에 함께 넣는 안은 기각한다.** `TGT-02` 가
"현재 예약·접수 업무의 상태는 완료이력으로 사용하지 않는다"고 못박아, 접수를 검진완료로 간주하게 된다.

### 4.5 변경이력 EAV 컬럼

```text
이력ID     BIGINT IDENTITY   PK. 기록 순서
기록일시   DATETIME2(0)      SP 의 @StoredNow
조작자명   NVARCHAR(50) NULL 인증되지 않은 자기신고 문자열 (04 §14 L4)
대상테이블 NVARCHAR(10)      수검자 · 예약접수 · 완료이력
대상키     BIGINT NULL       수검자ID 또는 업무ID
컬럼명     NVARCHAR(30)      바뀐 컬럼 하나
변경전     NVARCHAR(4000)    NULL 이면 값이 없던 상태
변경후     NVARCHAR(4000)    NULL 이면 값을 지운 상태
```

- **성공한 데이터 변경만** 기록한다. 바뀐 컬럼 1개당 1행이다.
- 값이 실제로 바뀐 컬럼만 남긴다. 같은 값으로 덮어쓴 것은 기록하지 않는다.
- `NVARCHAR(4000)` 은 자르는 상한이다. `수검자.비고` 가 넘으면 잘린다 ―
  감사 기록은 복원 근거가 아니라 열람용이다(`00` CP-06 이 이미 그렇게 정하고 있다).
- 기록은 여전히 트랜잭션 밖에서 자체 `TRY/CATCH` 로 한다(`04` §8.7.4). 실패해도 업무를 되돌리지 않는다.
- Trigger 를 쓰지 않으므로 Write SP 8개가 컬럼별 비교를 직접 쓴다. 이것이 이 결정의 구현 비용이다.
