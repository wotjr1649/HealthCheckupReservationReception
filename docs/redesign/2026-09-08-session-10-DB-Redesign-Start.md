# db-redesign 착수 — 결정 12건과 그 근거

작업 디렉터리는 `D:/AIDEV/HealthCheckupReservationReception` 이다.
**세션을 저장소 루트에서 연다.** 루트 `AGENTS.md` 와 `database/AGENTS.md` 가 규칙 본문이고
이 문서는 그 위에 얹는 것이지 대체하지 않는다.

이 문서는 **결정과 그 근거, 그리고 착수점**만 담는다. 설계 본문은 없다 — 그것을 쓰는 것이
이번 작업이다. 설계를 안 해 본 상태에서 미리 쓴 계획은 첫 단계에서 바뀐다.

## 1. 지금 참인 것

```text
브랜치      main = db-drift = 9b18847   원격 origin 과 일치. 작업트리 clean
원격        https://github.com/wotjr1649/HealthCheckupReservationReception  (PUBLIC)
```

Phase 4 는 끝났고 `db-drift`(게이트 위생)도 `main` 에 안착했다. **다음은 계약 변경이다.**

상태를 읽지 말고 **돌려서 본다.**

```bash
cd database
```

마지막 창 안 회귀는 `database/artifacts/logs/full_test_run_drift.log` 다
(`exit 0 · PASS 365 · FAIL 0 · SKIP 2 · NOT RUN 1`). 회차 실측과 Gate 판정의 **단일 출처는
`06` §42** 이고, 이 문서는 그것을 베끼지 않는다.

끝내지 못하면 되돌린다. 게이트가 red 인 커밋을 남기지 않는다.

## 3. 결정 12건 — 사용자와 두 라운드 grilling 으로 정했다

바꾸려면 사용자에게 물어라. 근거는 §4 에 있다.

| # | 결정 |
|---|---|
| 1 | 위생(`db-drift`)과 계약 변경을 분리한다 — 위생은 **완료** |
| 2 | 계약 변경 브랜치 이름은 `db-redesign` |
| 3 | **`00` 업무정책을 연다** — 정책이 틀렸다는 사용자 판단 |
| 4 | 휴무일은 **1 테이블 + 구분코드**(법정/대체/자체). 2 테이블로 나누지 않는다 |
| 5 | 자체휴무일은 **화면에서 CRUD** 한다 — SP 신설 |
| 6 | 공휴일 SEED 는 **2년치를 전부 펼쳐 하드코딩**한다 (대체공휴일 포함) |
| 7 | 그 SEED 의 **만료를 경고하는 게이트**를 함께 만든다 |
| 8 | 동시성 토큰을 **행버전으로 통일**한다 |
| 9 | 컬럼 순서를 **PK → 감사 → FK → 일반** 으로 고정한다 |
| 10 | **`03` 화면설계까지 지금 쓴다** (구현은 Phase 5) |
| 11 | Phase 5(WinForms 구현)는 **미룬다** |
| 12 | `06` §42 `G05` 근거를 **포인터로 바꾼다** — 이번 재봉인에 포함 |

`[!]` **미검증 하나.** 대체공휴일 규칙은 2021·2023 에 법이 바뀌었고 설·추석·부처님오신날은
음력이다. **현행 법령을 확인하고 넣어라** — 기억으로 적지 마라. 확인 전에는 SEED 를 쓰지 않는다.

## 4. 그 결정을 낳은 실측 — 다시 재지 마라

### 행버전 — "빠져 있다" 가 아니라 "토큰이 다르다"

```text
ROWVERSION 등장   deploy/01_Schema.sql:178  단 1건 (예약접수)
수검자 수정 SP    deploy/05_Procedures_Patient_Write.sql:611
                  WHERE [수검자ID]=@수검자ID AND [최종수정일시]=@기존최종수정일시
                  @@ROWCOUNT=0 -> 결과코드 600 "다른 사용자가 변경했습니다"
```

`수검자` 는 **이미 낙관적 제어를 한다.** 토큰이 `ROWVERSION` 이 아니라 `최종수정일시` 일 뿐이고,
`600` 이 예약접수의 `601` 에 대응한다. lost update 구멍은 없다.

대가는 같은 파일의 `+4ms` 보정 코드다 — `DATETIME` 은 1/300초(약 3.33ms) 해상도라 같은 눈금에
두 번 수정하면 토큰이 안 변한다. 감사 정보와 동시성 토큰이 한 컬럼에 겹친 결과다.
**그래서 결정 8은 "추가" 가 아니라 "통일" 이다.**

### 컬럼 순서 — 바꿔도 깨지는 것이 없다

```text
SELECT *                  0건 (deploy · tests 전체)
컬럼 목록 없는 INSERT      0건
05 §16.2                  "이름으로 읽는다. 순서에 기대지 않는다"
clean-create              ALTER 가 아니라 CREATE 를 고치면 끝이다
```

비용은 하나뿐이다 — `DOC-004` 가 "배포 DDL 순서 = 문서 순서" 를 대조하므로
`deploy/01_Schema.sql` 과 `04` §8 을 **같이** 고쳐야 한다.

지금 상태가 문제의 실례다: `수검자` 는 감사 컬럼이 15·16번이라 컬럼을 하나 더하면
감사 컬럼이 중간에 파묻힌다.

### 휴무일 — 업무 판정 질의는 두 줄뿐이다

```text
휴무일 질의 16곳
  deploy 5곳  ├ 03_Functions.sql:69·71   업무일 판정. **실질은 여기 둘뿐**
              └ 02_Seed:10·43 · 08_Verify:52   가드·건수
  tests 11곳  전부 건수 확인이거나 "오늘이 휴무일인가" 가드
```

2 테이블로 나눠도 `UNION` 을 넣을 곳은 두 줄이다. 그런데 **날짜 중복 금지(HOL-04)를 PK 로
못 지키게 된다** — 그래서 결정 4가 1 테이블이다.

운영시간·마감은 `deploy/03_Functions.sql` 이 확정한다.

```text
운영시간   09:00 <= 현재시각 < 18:00
마감       NORMAL AM 10:00 / PM 15:00      RECEPTION AM 11:00 / PM 16:00
```

### `00` 이 제안 셋을 정면으로 막는다

```text
HOL-03  공휴일 API·외부 달력을 연계하지 않는다. **공휴일과 자체 휴진일을 동일 Master로 관리**
HOL-04  논리 최소정보는 휴무일 / 휴무일명 / 사용여부 / 비고. 날짜 중복 금지
HOL-05  관리 UI 를 구현하지 않고 Seed 로 제공한다. 테스트용 평일 1건 · 토요일 1건
```

`03` 의 "범위 밖" 목록에도 **"휴무일/검사 Master/AEX 관리자 CRUD"** 가 이미 들어 있다
(공단 API·수납과 같은 급). 결정 3·5·10 이 그것을 되돌린다.

## 5. 반드시 지킬 것

```text
계약을 바꾸는 것이 이번 작업이다 — 다만 바꾼 것을 문서·SQL·시험·게이트에 **동시에** 반영한다
재봉인은 파일과 해시를 같은 커밋에 (루트 AGENTS.md §2.2)
실행하지 않은 검증을 PASS 로 적지 않는다 (database/AGENTS.md §10)
같은 값을 두 곳에 두지 않는다 — 적으려면 그 값을 보는 검사를 함께 만든다 (루트 §6)
.sql 은 UTF-8 with BOM · 한글 리터럴에 N 접두사 (database/AGENTS.md §5. V22·V16 이 판정)
sqlcmd 는 항상 -b -I -u (§6)
허용 T-SQL 목록 밖을 쓰지 않는다 (§7). COLLATE · FOR XML · STRING_AGG 도 밖이다
```

`[!]` **회귀 밖의 게이트는 썩는다.** 새 게이트를 만들면 `database/scripts/test.sh` 안에 넣고
**RED 로 확인한다** — 일부러 깨뜨려 FAIL 이 나는지 본다. 이 저장소에서 게이트가 초록인 채
아무것도 검증하지 않던 사건이 여러 번 나왔다(`06` §44.8).

## 6. 창 안 회귀가 필요하면 — 시각은 사람이 옮긴다

시각 의존 경로(`CWR-006`·`CWR-009`·`CON-005`·`CON-008`)는 특정 창에서만 성립한다.

```text
CON 창    월~토 11:00~15:50   PM 접수마감 16:00 - 10분 여유
계약 창   월~토 11:10~15:50   AM 마감(11:00)이 지나야 CWR-009 가 성립한다
```

창 밖이면 **머신 시각을 옮겨** 만든다. TVF 상수를 고치는 우회는 금지다 —
`rebuild` 가 되돌리고, 배포 원본을 고치면 다른 제품을 시험한 `PASS` 가 된다.

```powershell
Set-Date -Adjust (New-TimeSpan -Hours -N)   # 사람이 실행한다
Set-Date -Adjust (New-TimeSpan -Hours  N)   # 끝난 뒤 같은 크기로 되돌린다
```

`[!]` **바꾸는 것도 되돌리는 것도 사람이 한다** — 되돌리지 못한 채 죽는 자동화를 남기지 않는다
(`database/scripts/run-con-window.sh` 머리말). 옮긴 뒤 셸과 SQL Server **양쪽** 시각을 확인한다.

`[!]` **옮긴 동안에는 커밋하지 않는다.** 회차 `A` 때 시계를 되돌리며 커밋 날짜가 비단조가 되어
(`e07adf7` 이 그 뒤 10커밋보다 늦다) 로그 신선도를 시각으로 판정할 수 없게 된 적이 있다.
